# 순기 식단: 아키텍처와 임상 규칙 명세

사상체질(소음인 기본, 4체질 확장)과 후천적 병리 상태(기체증·부교감 저하·양약 복용·직장인 식생활)를 입력받아
식재료·반찬·야식·시간대를 판정하는 웹앱이다. 이 문서는 **규칙이 코드 어디에 있고, 점수가 어떻게 계산되는지**를 적는다.

> 이 앱은 진료·처방을 대신하지 않는다. 사상 식품 분류는 문헌·임상가마다 차이가 있으며, 약물-식품 상호작용 규칙은 일반 원칙이다. 개별 약물은 처방의·약사 확인이 필요하다.

---

## 1. 바운디드 컨텍스트 (DDD)

```
src/
├─ domain/                    순수 TypeScript. React·브라우저 의존 없음 → 전부 단위 테스트 가능
│  ├─ shared/time.ts          HH:MM, 자정을 넘는 원형 구간, 날짜 연산
│  ├─ profile/                UserProfile (명세 §5-1) + 기본 임상 케이스
│  ├─ food/                   SasangFoodItem (명세 §5-2) + 식재료 마스터 DB 86종
│  ├─ constitution/matrix.ts  4체질 매트릭스(명세 §4) → 가중치 수치화, 병리 상태 레이어
│  ├─ scoring/                규칙 엔진: 식재료 점수(engine.ts) → 반찬 점수(dish.ts)
│  ├─ medication/             양약 60분 세이프가드 (명세 §3-3)
│  ├─ cafeteria/              반찬 카탈로그 90종, 메뉴판 파서, 식판 시뮬레이터 (명세 §3-4)
│  ├─ night/funnel.ts         야식 방어 3단계 퍼널 상태 기계 (명세 §3-5)
│  └─ log/                    DailyHealthLog (명세 §5-3), 패턴 분석, 레드 플래그
├─ infra/storage.ts           HealthRepository 포트 + localStorage 어댑터
└─ ui/                        React 화면 5개 (오늘·식판·야식·기록·내 몸)
```

의존 방향은 `ui → domain`, `ui → infra → domain(타입)` 한 방향뿐이다. 서버 동기화가 필요해지면
`HealthRepository`만 새로 구현하면 된다.

## 2. 규칙 엔진: 식재료 점수

`scoreFood(food, cookingContext, profile)` → `{ score 0~100, verdict, hits[] }`

모든 가감점은 `RuleHit { ruleId, label, delta }`로 남는다. UI의 "왜 이 판정인가"는 이 배열을 그대로 보여 준다.

| 순서 | 규칙 | 내용 |
|---|---|---|
| R0 | 체질 적합도 기본점 | BEST 70 · GOOD 55 · CAUTION 35 · AVOID 15 |
| G1 | 카페인 전역 금기 | 양약 복용 **또는** 부교감 저하 → 차단 |
| G2 | 자몽류 전역 금기 | 양약 복용 → 차단 (CYP3A4 억제) |
| G3 | 양약 상호작용 식품 | `medInteractionRisk` + 양약 복용 → 차단 (고농축 홍삼 등) |
| R1 | 병리 상태 차단 | 기체증 → 인삼·홍삼(`GINSENG`) 일시 차단 |
| T | 실효 한열 | 고유 한열에 제공 온도 보정 후 체질 가중 (아래) |
| Q | 순기 점수 | `(qiMovingScore − 2) × 체질 가중 × 병리 배율` — 기체증 ×2 |
| E | 천연 소화효소 | 체질 가중 × 병리 배율 — 기체증 ×1.5 |
| V | 점성 페널티 | 기체증: 점성 4 이상이면 `(점성 − 3) × 8` 감점 |
| TG | 태그 가중 | 체질·병리별 (소도 +6, 단맛 정체 −10, 청열 +12 …) |
| R2 | 조리법 보정 | 생식 −25 / 화식+온열양념 +20 / 튀김 감점 (체질별 배율) |

판정 임계값: **BEST ≥ 68 · GOOD ≥ 50 · CAUTION ≥ 30 · 그 아래 AVOID**.
조정 요소가 없으면 기본점이 같은 등급에 떨어지도록 기본점 바로 아래에 두었다.

### 실효 한열 (조리·온도 보정)

- 차갑게 제공 → 한 단계 차게 (냉면: 량 → 한)
- 뜨겁게 제공 → 한 단계 따뜻하게
- 익혀서 따뜻하게 제공 → **소음인만** 한 단계 따뜻하게 (`warmCookedShift`).
  비위가 찬 소음인에게는 익혀 먹는 것 자체가 보정이지만, 열 체질에게 따뜻한 밥이 해롭지는 않기 때문이다.

### 명세와 다르게 해석한 지점

| 명세 | 구현 | 이유 |
|---|---|---|
| 스키마 주석 `warmCookedBonus +15` vs 가드레일 §3-2 `+20` | **+20** | 가드레일이 하드 제약이므로 우선 |
| "화식+온열양념일 때만 가산" | 화식 단독은 0점, 단 소음인은 실효 한열이 한 단계 올라감 | 가산점 규칙은 그대로 지키고, 온도 효과는 한열 축에서 따로 반영 |
| 카페인·자몽 "전역 금기" | 양약 복용(자몽) / 양약 또는 부교감 저하(카페인)일 때 차단, 아니면 감점 | 금기의 근거가 약물·자율신경이므로 조건이 꺼지면 감점으로 완화 |
| 카테고리 5종 | `DAIRY`, `BEVERAGE` 추가 | 60분 세이프가드가 유제품을 별도로 다룸 |

### 임상적으로 추가한 규칙

- **단맛 정체(甘令人中滿)**: 기체증에서 대추·꿀 등 단맛 −10. 명치가 막힌 상태에서 단 것은 중초를 더 막는다.
- **매운 반찬 감점**: 소음인도 자극적으로 매운 반찬은 위점막을 자극해 −15.
- **레드 플래그**: 명치 답답함 4 이상 3일 연속 경고, 7일이면 진료 권고. 흉통·흑변·연하곤란 등은 항상 노출.
  명치 통증은 드물게 심장 질환의 신호이므로 식단 앱이 끝까지 붙잡고 있으면 안 된다.

## 3. 반찬 점수와 식판 시뮬레이터

`scoreDish(dish, profile)`

1. 주재료 점수를 비중으로 가중평균 (양념은 `warmSeasoning` 플래그로 표현)
2. 주재료 중 하나라도 차단이면 반찬 전체 **차단** (예: 삼계탕 → 인삼)
3. 체질별 식판 정책 가감 (`CONSTITUTION_MATRIX[*].cafeteria`)
4. **하드 룰** 태그가 있으면 점수와 무관하게 **거르기**
   - 소음인: 돼지고기 · 튀김 · 생야채 샐러드 · 면류 (명세 §3-4)
5. 담기 ≥ 55 · 조금만 ≥ 35 · 그 아래 거르기
6. 담기·조금만 판정이어도 과일·유제품·한방차가 들어 있고 식사 시각이 복약 창에 걸리면 **보류** (`14:01부터`)

**식사량**: 전날 기록이 대체식이든 일반 야식이든 *무언가 먹었으면* 다음 날 **아침만** 50%. 예시 기록은 이 판단에 쓰지 않는다.

### 메뉴판 파서

`parseMenu("백미밥, 소고기무국, 제육볶음…")`

1. 쉼표·줄바꿈·슬래시로 나누고, 구분자가 없으면 공백으로 나눈다
2. 카탈로그 이름·별칭 **정확 일치**
3. **끝이 같은** 부분 일치 중 가장 긴 것 (돼지고기김치찌개 → 김치찌개, 김치볶음밥 ≠ 김치)
4. 부분 일치가 튀김·생식·면·냉·돼지 신호를 놓치면 추론을 믿는다
5. 키워드 추론: 재료(정규식 60여 개) + 조리법(접미사) + 태그 → 임시 반찬 생성
6. 그래도 모르면 "판별 불가"로 따로 보여 주고 주재료를 함께 적도록 안내

## 4. 양약 60분 세이프가드

- 복약 시각마다 `[t−60, t+60]` 창. 자정을 넘는 창 지원 (23:30 → 22:30–00:30)
- 창이 겹치면 연쇄된 마지막 창 끝까지 미룬다 (12:00·13:00 복약 → 14:01부터)
- 제한 대상: 한방차(`HERBAL_TEA` 태그) · 유제품 · 과일. 보리차·숭늉 같은 곡물차는 제외
- 화면: 오늘 탭의 24시간 띠, 식판의 "보류", 야식 Step 1 음료 교체에 공통으로 쓰인다

## 5. 야식 방어 퍼널 (상태 기계)

```
WARM_DRINK ──(15분 타이머 / 건너뛰기)──▶ HUNGER_CHECK ──(6문항)──▶ SUBSTITUTE ──▶ DONE
                                                         │ FAKE: 먹지 않고 마무리 우선 노출
                                                         └ REAL: 대체식 우선 노출
```

- **Step 1 음료 교체**: 기본 음료(소음인 진피차)가 복약 창에 걸리면 미온수로 바꾸고 이유를 보여 준다.
  기본 케이스(21:30 복약)에서 21:00 야식 욕구가 오면 실제로 이 충돌이 난다.
- **Step 2**: 가짜 배고픔 신호 3개 이상 → FAKE
- **Step 3**: 체질별 대체식 후보를 반찬 엔진으로 점수화하고, 복약 창에 걸리는 것은 비활성화
- **기록**: 결과·15분 대기 여부·공복 시간을 그날 밤 기록에 자동 반영. 자정~04시는 전날 기록에 귀속.
  공복 시간은 방어 성공이면 저녁 식사 시각부터, 먹었으면 섭취 시각부터 다음 날 아침까지.

## 6. 체질 확장

새 체질 규칙은 `constitution/matrix.ts` 한 곳에서 끝난다.

- `weights`: 한열 가중, 순기·효소 가중, 생식 배율, 온열양념 보정, 튀김 감점, 태그 가중
- `cafeteria`: 담을 반찬 가산, 하드 룰, 감점, 밥 안내
- `nightDrinkId`, `nightSubstituteIds`: 야식 퍼널 음료와 대체식

병리 상태(`SUB_CONDITION_SPECS`)는 체질과 독립된 레이어라서, 예컨대 "소음인 + 허한증"으로 바꾸면
인삼 차단이 풀리고 한열·생식 배율이 커진다.

4. **체질 진단 설문**: 지금은 체질을 직접 고른다. QSCC II 등 설문은 보조 지표로만
