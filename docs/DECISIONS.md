# 결정 기록

사용자가 정한 것(D1~D8)과, 구현하면서 스스로 정한 기본값(S1~)을 구분해서 적는다.
바꾸고 싶으면 "어디를 고치면 되는가" 열을 보면 된다.

## 사용자가 확정한 결정

| ID | 결정 | 구현 위치 |
|---|---|---|
| D1 | 1인 전용, 로그인 없음, 기기에만 저장 + JSON 백업·복원 | `infra/storage.ts`, `domain/backup/backup.ts`, 알림·백업 화면 |
| D2 | 다음 날 아침: 일반 야식 50% · 대체식 75% · 그 외 100%, 점심은 항상 100% | `domain/log/types.ts` `morningPortionAfter`, `cafeteria/tray.ts` `portionFor` |
| D3 | 카페인·자몽은 조건이 있을 때만 차단, 아니면 '주의' | `scoring/engine.ts` (G1·G2·G-CAP) |
| D4 | 김치(소음인·기체증): 배추김치·깍두기 조금만, 신김치·묵은지·차가운 김치 거르기 | `scoring/dish.ts` (D4), `cafeteria/dishes.ts` |
| D5 | 약 이름 입력 → 약물별 음식 규칙, 사전에 없으면 일반 규칙 + 약사 확인 | `medication/drugs.ts`, 약 화면 |
| D6 | 저녁도 추천, 마감은 취침 3시간 전 | `meal/recommend.ts`, 저녁 화면 |
| D7 | 홈 화면 설치(PWA) + 알림 | `public/manifest.webmanifest`, `public/sw.js`, `reminders/` |
| D8 | 프롬프트는 Claude Code용 | `docs/prompts/sungi-meta-prompt-v2.md` |

## 스스로 정한 기본값

| ID | 정한 것 | 이유 | 바꾸려면 |
|---|---|---|---|
| S1 | 주말(토·일)은 아침·점심도 집밥 모드. 공휴일은 날짜 데이터가 없어 사용자가 저녁 화면에서 '쉬는 날'로 직접 표시 | 구내식당은 평일에만 이용 | `meal/recommend.ts` `isHomeDay` |
| S2 | 알림은 `.ics`(캘린더 매일 반복)가 기본, 앱이 열려 있을 때만 브라우저 알림 | 서버가 없어 백그라운드 푸시를 보장할 수 없음. Web Push는 이번 범위 밖 | `reminders/schedule.ts` |
| S3 | `.ics`는 타임존 없는 기기 로컬 시각(floating time) | 해외·시간대 변경에도 같은 시각에 울림 | `reminders/ics.ts` `dtLocal` |
| S4 | 약물 사전의 모든 규칙은 `verified: false` | 식약처 DUR·허가사항 원문을 대조하지 못했음. 화면마다 "약사 확인 필요" 표시 | `medication/drugs.ts`. 원문 대조 후 `verified: true`와 출처(문서명·확인일)로 교체 |
| S5 | 술: 약 금기가 있으면 차단, 없으면 기체증·부교감 저하에서 '주의' | H8 | `scoring/engine.ts` |
| S6 | '주의'로 고정된 재료가 든 반찬은 식판에서 '거르기' | "조금만"은 허용으로 읽혀 약 병용 주의에 위험한 안내가 됨 | `scoring/dish.ts` D-CAP |
| S7 | 배추김치·깍두기의 제공 온도를 '상온'으로 표시, 신김치·동치미·물김치만 '차가움' | D4의 "차가운 김치"를 신맛·찬 국물 김치로 해석 | `cafeteria/dishes.ts` |
| S8 | 저녁이 취침 5시간 이상 전이면 양을 줄이지 말고 단백질을 충분히 | 늦은 허기 예방 | `meal/recommend.ts` `EARLY_DINNER_GAP_MIN` |
| S9 | 저녁을 '거름·가볍게'로 기록한 날 야식 퍼널은 Step 2를 건너뜀 | 이 경우의 허기는 진짜일 가능성이 높음. 기록이 없으면(기본값) 건너뛰지 않음 | `night/funnel.ts` `finishWaiting` |
| S10 | 8시간 넘게 지난 야식 퍼널은 이어서 보여 주지 않음 | 어제 밤 타이머가 오늘 아침에 떠 있는 문제 방지 | `ui/store.ts` `freshFunnel` |
| S11 | 앱 형태의 서비스 워커는 앱 셸만 캐시(구글 폰트는 브라우저에 맡김) | 오프라인에서도 열리게 하되 개인 데이터는 캐시하지 않음 | `public/sw.js` (배포마다 `CACHE` 버전 올리기) |
| S12 | claude.ai Artifact 미리보기에서는 서비스 워커·파일 다운로드·알림이 막힘 → 서비스 워커는 등록하지 않고, 다운로드는 '내용 복사' 칸으로 대체 | 샌드박스 제약 | `ui/screens/Data.tsx` |

## v3: 식단 중심으로 정리 (사용자 요청)

요청: 건강관리 느낌을 줄이고, 아침·점심은 사용자가 입력해 평가한 뒤 저녁을 거기에 맞춰 추천한다.

| ID | 정한 것 | 이유 | 위치 |
|---|---|---|---|
| S13 | 첫 화면을 ‘오늘 식단’ 한 흐름(아침 입력 → 점심 입력 → 저녁 추천)으로. 하단 탭은 3개(오늘 식단·야식·설정) | 건강 기록이 아니라 "오늘 뭘 먹었고 저녁은 뭘 먹을지"가 중심 | `ui/screens/Today.tsx`, `ui/App.tsx` |
| S14 | 컨디션 기록·복약 시계·알림·백업은 삭제하지 않고 설정 안으로 옮김 | 데이터와 기능은 유지, 첫 화면에서만 뺌 | `ui/App.tsx` 하위 메뉴 |
| S15 | 식판 시뮬레이터(먹기 전 메뉴판 판정)는 ‘먹기 전에 메뉴판으로 골라 보기’ 링크로 유지 | 먹기 전 선택과 먹은 뒤 평가를 둘 다 지원 | `ui/screens/Tray.tsx` |
| S16 | 먹은 반찬의 평가 문구는 일상 말로(좋아요·무난·아쉬워요·피할 것·시간 겹침). 한열·화식 같은 근거는 식판·판정기의 ‘판정 근거’ 안에서만 보임 | 건강·한방 용어를 첫 화면에서 걷어내기 | `domain/meal/day.ts` `plainReason` |
| S17 | 끼니 등급: 아쉬운·피할 반찬이 40% 이상이거나 차단 항목이 있으면 ‘부담될 수 있는 한 끼’, 아쉬운 게 없고 좋은 반찬이 절반 이상이면 ‘좋은 한 끼’ | 임상 보정이 아닌 설계값 | `domain/meal/day.ts` `evaluateEaten` |
| S18 | 저녁 맞춤 규칙: 찬 음식(소음인) → 따뜻한 국물, 기름진 반찬 → 담백한 생선·두부·익힌 무 + 양 가볍게, 밀가루 → 밥 위주, 단백질 없음 → 계란·두부·생선, 익힌 채소 없음 → 나물 2가지, 끼니 거름 → 든든하게, 오늘 먹은 단백질·반찬은 피함 | 사용자가 말한 "평가한 이후 저녁 추천" | `domain/meal/day.ts` `buildDinnerContext` |
| S19 | 저녁 후보는 여전히 식판과 같은 규칙 엔진의 ‘담기’ 판정만 사용(돼지고기·튀김·샐러드·면은 아무리 가산점이 있어도 안 나옴) | 맞춤 가산이 가드레일을 넘지 못하게 | `domain/meal/recommend.ts` |
| S20 | 끼니 입력은 날짜별로 저장하고 60일이 지나면 정리, 백업에 포함(백업 버전 3). 이전 백업도 읽힘 | 기록이 기기에만 있으므로 | `domain/meal/store.ts`, `domain/backup/backup.ts` |

## 확인이 필요한 의학 정보

- 약물 사전 10종·규칙 12개 전부 미검증 (S4)
- 분류가 갈리는 식품: 무·마(산약, 고전 분류상 태음인 식품), 대추·귤(소음인 분류는 문헌마다 다름), 보리(소음인 금기 vs 일반 건강식)
- 식판 판정 임계값(담기 55 · 조금만 35)과 점수 가중치는 임상 근거로 보정한 값이 아니라 설계값. 한의사 검토 필요
