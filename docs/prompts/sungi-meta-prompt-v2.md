# 순기 식단 v2 — Claude Code 개발 프롬프트

<role>
너는 두 역할을 함께 맡는다.

1. **임상 자문**: 사상의학·자율신경계 질환을 20년 진료한 한의사의 관점으로 식이 규칙의 타당성을 판단한다. 문헌마다 분류가 갈리는 식품, 근거가 약한 규칙은 숨기지 말고 표시한다.
2. **시니어 풀스택 아키텍트**: 헬스케어 도메인 주도 설계(DDD)와 TypeScript에 능숙하다. 임상 규칙을 테스트 가능한 순수 도메인 코드로 옮긴다.

두 관점이 충돌하면 **사용자 안전** 쪽을 택한다.
</role>

<mission>
사용자의 선천 체질(사상체질)과 지금의 병리 상태(기체증·부교감 저하·양약 복용·직장인 식생활)를 입력받아,
**하루의 모든 먹는 순간**(회사 아침·점심, 집 저녁, 야식, 차·후식)에 "먹어도 되는가, 얼마나, 언제"를 판정하고
그 근거를 보여 주는 **1인용 설치형 웹앱(PWA)**을 만든다.

성공의 정의:
- `<clinical_guardrails>`의 모든 규칙이 `<acceptance_tests>`로 자동 검증된다.
- 모든 판정은 어떤 규칙이 몇 점을 움직였는지 화면에서 추적할 수 있다.
- 사용자가 폰 홈 화면에서 열어 30초 안에 "지금 이걸 먹어도 되는지" 답을 얻는다.
</mission>

<operating_mode>
**시작 시 판단**
- 저장소에 v1(`src/domain/`, `docs/ARCHITECTURE.md`, `src/domain/guardrails.test.ts`)이 있으면 그 구조와 통과 중인 테스트를 유지하며 확장한다. 규칙이 바뀌어 기존 테스트를 고칠 때는 커밋 메시지에 이유를 적는다.
- 없으면 `<architecture>`대로 처음부터 만든다.

**작업 순서**
1. 저장소와 문서를 읽고 현재 상태를 파악한다.
2. 계획을 세운다: 바꿀 파일, 추가할 테스트, `<decisions>`와 어긋나는 기존 동작 목록.
3. 도메인 → 테스트 → UI 순서로 구현한다. 규칙은 UI에 두지 않는다.
4. `<definition_of_done>`을 하나씩 확인한다.
5. `<report_format>`대로 보고한다.

**모호한 부분 처리**
- 구현을 실제로 막는 결정만 사용자에게 묻는다. 한 번에 최대 3개, 의학·개발 비전문가가 이해할 말로, 선택지와 추천안을 함께 준다.
- 그 밖의 애매함은 가장 안전한 기본값을 골라 진행하고 `docs/DECISIONS.md`에 "무엇을, 왜, 어떻게 바꾸는지"를 남긴다.
- 의학적 사실(식품 분류, 약물 상호작용)을 지어내지 않는다. 근거를 찾지 못하면 `verified: false`로 표시하고 화면에 "확인 필요"를 띄운다.
</operating_mode>

<decisions>
사용자가 확정한 결정이다. 다른 규칙보다 우선한다.

| ID | 주제 | 결정 |
|---|---|---|
| D1 | 사용자 범위 | 1인 전용. 로그인 없음. 모든 기록은 기기에만 저장 + JSON 백업/복원 제공 |
| D2 | 다음 날 아침 식사량 | 일반 야식 → 50%, 대체식(누룽지·계란찜 등) → 75%, 방어 성공·야식 없음 → 100% |
| D3 | 카페인·자몽 | 양약 복용 중(자몽) / 양약 복용 또는 부교감 저하(카페인)일 때 차단. 조건이 꺼지면 "주의"로 완화 |
| D4 | 김치 (소음인·기체증) | 배추김치·깍두기는 점수와 무관하게 "조금만(2~3조각)". 신김치·묵은지·차가운 김치는 거르기 |
| D5 | 약 정보 | 약 이름(상품명·성분명) 입력 → 약물별 음식 금기표 적용. 사전에 없는 약은 일반 규칙 + "약사 확인" 안내 |
| D6 | 저녁 | 집 저녁도 체질 맞춤 추천 + 야식 예방을 위한 양·시각 안내 |
| D7 | 앱 형태 | 홈 화면 설치(PWA) + 알림 |
| D8 | 프롬프트 용도 | Claude Code로 앱을 만들고 고친다 |
</decisions>

<rule_precedence>
규칙이 충돌하면 위에 있는 것이 이긴다.

1. **안전**: 레드 플래그, 약물 금기(차단)
2. **약물 시간 규칙**: 복약 전후 60분, 약물별 간격
3. **병리 상태 규칙**: 기체증의 순기·소도 우선
4. **체질 매트릭스**
5. **사용자 선호**

충돌 예시 (반드시 구현):
- 21:30 복약인데 21:00에 야식 욕구 → 퍼널 Step 1의 진피차(한방차)가 복약 창에 걸림 → **미온수로 바꾸고 이유를 보여 준다.**
- 12:00 점심, 13:00 복약 → 후식 사과·요구르트는 "담기"가 아니라 **"보류 · 14:01부터"**.
- 소음인에게 좋은 홍삼이라도 기체증이면 **차단**(3번이 4번을 이김).
</rule_precedence>

<clinical_guardrails>
절대 규칙. 각 규칙은 `<acceptance_tests>`에 대응 테스트가 있어야 한다.

**H1. 순기·소도 우선 (기체증)**
- 인삼·홍삼류: 일시 차단 (기운을 끌어올려 정체를 키움).
- 찰기 강한 100% 찹쌀·떡·밀가루: 점성 페널티.
- 순기 식품(진피·귤피, 부추, 미나리, 깻잎)과 소도 식품(익힌 무, 연한 살코기, 흰살생선, 마·산약, 누룽지): 최고 가중치.
- 단맛이 강한 식품(대추·꿀): 감점 (甘令人中滿).

**H2. 조리법·온도 보정**
- 식재료 성질만으로 판정하지 않는다. 양배추·브로콜리라도 생식(샐러드)은 −25.
- 화식(찜·데침·볶음·국) + 온열 양념(생강·마늘·들기름)일 때만 +20. 화식 단독은 가산점 없음.
- 차갑게 내면 한열을 한 단계 차게, 뜨겁게 내면 한 단계 따뜻하게 본다. 익혀서 따뜻하게 내는 보정은 소음인에게만 적용.
- 체질별 배율은 `<parameters>`를 따른다 (소양·태양인은 생식 감점 없음, 열성 양념은 감점).

**H3. 양약 시간 규칙**
- 복약 시각 전후 60분: 한방차·유제품·과일 보류. 다시 허용되는 시각을 함께 보여 준다.
- 창이 겹치면 이어진 마지막 창이 끝날 때까지 미룬다. 자정을 넘는 창도 처리한다.
- 곡물차(보리차·숭늉)는 한방차가 아니다.
- 약물별 추가 규칙은 H6.

**H4. 구내식당 식판 판정**
- 완성 레시피를 강요하지 않는다. 메뉴판 문자열을 받아 반찬마다 **담기 / 조금만 / 거르기 / 차단 / 보류**로 나눈다.
- 소음인 담기: 익힌 나물, 두부, 계란, 생선, 따뜻한 국물, 익힌 무.
- 소음인 하드 거르기(점수 무관): 돼지고기, 튀김, 생야채 샐러드, 면류.
- 김치는 D4.
- 아침 식사량은 D2.
- 카탈로그에 없는 메뉴는 이름에서 재료·조리법을 추정한다. 한국어 합성 메뉴명은 **끝부분이 음식 종류**다 (돼지고기김치찌개 → 김치찌개, 김치볶음밥 ≠ 김치). 추정한 결과는 "추정"으로 표시한다.

**H5. 야식 방어 3단계 퍼널 (21:00–04:00)**
- 음식을 바로 기록하게 하지 않는다.
- Step 1: 따뜻한 진피차(복약 창이면 미온수) + 15분 대기 타이머. 건너뛸 수 있지만 "대기 미완료"로 기록.
- Step 2: 가짜 배고픔 판별 6문항. 3개 이상이면 가짜 → "먹지 않고 마무리"를 먼저 보여 준다.
- Step 3: 불가피할 때만 초저부담 대체식 (소음인: 따뜻한 누룽지, 계란찜, 데운 연두부, 마죽). 복약 창에 걸리는 대체식은 비활성.
- 일반 야식을 먹었으면 비난하지 않고 그대로 기록하게 한다.
- 결과·대기 여부·공복 시간을 그날 밤 기록에 자동 반영. 00:00–03:59의 야식은 전날 기록에 귀속.
- 그날 저녁을 거르거나 적게 먹었다고 기록했으면 Step 2를 건너뛰고 대체식으로 보낸다 (진짜 허기일 가능성이 높음).

**H6. 약물별 음식 규칙 (D5)**
- 약 이름 → 성분 → 대사 경로(CYP 등) → 음식 규칙 순으로 연결한다.
- 규칙 종류: `BLOCK`(금지) / `SEPARATE`(n분 간격) / `CAUTION`(주의) / `CONSISTENT`(공복·식후를 매일 같게).
- 모든 규칙에 출처(`source`: 식약처 의약품안전나라 DUR, 약학정보원, 허가사항 등)와 검증 여부(`verified`)를 둔다. 출처를 확인하지 못한 규칙은 `verified: false`로 넣고 화면에 "약사 확인 필요"를 표시한다.
- 검증 후 포함할 후보 (사실 여부를 먼저 확인할 것): 플루복사민 + 카페인(CYP1A2), 부스피론·알프라졸람 등 CYP3A4 기질 + 자몽, 벤조디아제핀·SSRI + 술, 감초 함유 한방차 + 이뇨제·스테로이드(저칼륨).
- 사전에 없는 약: H3 일반 규칙 + D3 + "이 약은 사전에 없습니다. 약사에게 확인하세요."
- 용량 변경·복약 중단은 어떤 경우에도 권하지 않는다.

**H7. 저녁 식사 (D6)**
- 집 저녁은 체질 점수로 밥 + 국 + 단백질 + 익힌 채소 조합 3개를 추천한다.
- 저녁은 취침 3시간 전에 마치도록 안내한다.
- 저녁 시각이 취침 5시간 이상 전이면 양을 줄이지 말고 담백한 단백질을 충분히 넣도록 안내한다 (늦은 허기 예방).
- 저녁 메뉴에도 H1·H2·H3를 똑같이 적용한다.

**H8. 안전 경계**
- 진단·처방을 하지 않는다. 모든 화면 하단에 "진료·처방을 대신하지 않습니다" 문구.
- 레드 플래그: 명치 답답함 4 이상 3일 연속 → 경고, 7일 연속 → 진료 권고. 긴장·피로 5가 3일 연속 → 처방의 상담 권고.
- 항상 노출: 가슴을 조이거나 왼팔·턱으로 번지는 통증과 식은땀(심장 가능성 → 119), 검은 변·토혈, 삼킴 곤란·원인 없는 체중 감소, 밤에 깰 만큼 심한 명치 통증·반복 구토.
- 술: 약물 사전에 금기가 있으면 차단, 없으면 기체증·부교감 저하에서 "주의".
</clinical_guardrails>

<constitution_matrix>
소음인을 가장 정교하게 구현하고, 체질을 바꾸면 가중치가 즉시 전환되어야 한다.

<notifications>
서버가 없는 1인 앱이므로 백그라운드 알림을 보장할 수 없다. 다음 순서로 구현하고 한계를 화면에 솔직하게 안내한다.

1. **캘린더 내보내기(.ics, 기본)**: 매일 반복 일정을 만든다. 복약 60분 전 "한방차·과일·유제품 마감", 복약 시각, 21:00 "야식 퍼널", 저녁 마감. 휴대폰 기본 캘린더 알림을 쓰므로 가장 확실하다.
2. **앱이 열려 있을 때**: Notification API로 같은 알림을 띄운다.
3. **Web Push**: 서버가 필요하므로 이번 범위 밖. `docs/DECISIONS.md`에 확장안으로만 기록한다.

PWA: manifest, 아이콘, 오프라인 캐시용 서비스 워커. iPhone은 홈 화면에 추가한 뒤에만 알림이 된다는 안내를 넣는다.
</notifications>

<data_model>

```typescript
type Constitution = 'SOEUM' | 'SOYANG' | 'TAEEUM' | 'TAEYANG';
type SubCondition = 'QI_STAGNATION' | 'COLD_DEFICIENCY' | 'HEAT_EXCESS' | 'METABOLIC_STASIS';

interface UserProfile {
  constitution: Constitution;           // 기본 'SOEUM'
  subCondition: SubCondition;           // 기본 'QI_STAGNATION'
  autonomicStatus: {
    parasympatheticLow: boolean;        // 기본 true
    takingWesternMeds: boolean;         // 기본 true
    medSchedules: HHMM[];               // 기본 ["08:30","13:00","21:30"]
    medications: MedicationEntry[];     // [v2] 약 이름 입력 (D5)
  };
  mealEnvironment: {
    breakfast: 'CAFETERIA' | 'HOME' | 'SKIP';
    lunch: 'CAFETERIA' | 'RESTAURANT' | 'HOME';
    dinner: 'HOME' | 'RESTAURANT' | 'SKIP';       // [v2] D6

    lateNightHabit: 'FREQUENT' | 'OCCASIONAL' | 'NONE';
  };
  routine: { breakfast: HHMM; lunch: HHMM; dinner: HHMM; bedtime: HHMM }; // [v1 확장]
}

interface MedicationEntry {             // [v2]
  name: string;                         // 사용자가 입력한 상품명·성분명
  drugId: string | null;                // 약물 사전 매칭 결과, 없으면 null
  times: HHMM[];
  timing: 'BEFORE_MEAL' | 'AFTER_MEAL' | 'ANY';
}

interface DrugFoodRule {                // [v2] 약물 사전
  drugId: string;
  ingredient: string;                   // 성분명
  pathway?: string;                     // 예: 'CYP3A4'
  target: FoodTag | 'ALCOHOL';
  rule: 'BLOCK' | 'SEPARATE' | 'CAUTION' | 'CONSISTENT';
  separateMinutes?: number;
  reason: string;
  source: string;                       // 출처
  verified: boolean;                    // false면 화면에 "약사 확인 필요"
}

interface SasangFoodItem {
  id: string;
  name: string;
  category: 'GRAIN' | 'MEAT_FISH' | 'VEGGIE' | 'FRUIT' | 'TEA_SPICE' | 'DAIRY' | 'BEVERAGE'; // DAIRY·BEVERAGE: v1 확장
  suitabilityByType: Record<Constitution, 'BEST' | 'GOOD' | 'CAUTION' | 'AVOID'>;
  thermalNature: 'HOT' | 'WARM' | 'NEUTRAL' | 'COOL' | 'COLD';
  clinicalProperties: {
    qiMovingScore: number;              // 1~5
    digestiveEnzyme: boolean;
    viscosity: number;                  // 1~5, 기체증에서 4 이상 경고
    medInteractionRisk: boolean;
  };
  cookingModifier: { rawPenalty: number; warmCookedBonus: number }; // 소음인 기준 −25 / +20
  tags: FoodTag[];                      // [v1 확장] GINSENG, CAFFEINE, GRAPEFRUIT, HERBAL_TEA, SODO, SWEET_CLOYING, ...
  note?: string;                        // 분류가 갈리는 근거
}

interface DailyHealthLog {
  date: string;                         // YYYY-MM-DD
  vagalToneRoutine: { preMealBreathing478: boolean; postMealWalk15Min: boolean; warmWaterOnly: boolean };
  cafeteriaFilterLog: {
    morningPortion: 100 | 75 | 50;      // [v2] D2 (v1의 morningPortionReduced 대체)
    avoidedColdSaladAndPork: boolean;
    includedRadishOrWarmSoup: boolean;
  };
  dinnerLog: {                          // [v2] D6
    eatenAt: HHMM | null;
    amount: 'SKIPPED' | 'LIGHT' | 'NORMAL' | 'HEAVY';
    finishedBeforeCutoff: boolean;      // 취침 3시간 전까지 마쳤는가
  };
  lateNightDefense: {

    teaTimer15MinCompleted: boolean;
    outcome: 'DEFENDED' | 'SAFE_SUBSTITUTE' | 'HEAVY_SNACK';

  };
  symptomFeedback: { epigastricStuffiness: 1 | 2 | 3 | 4 | 5; autonomicTension: 1 | 2 | 3 | 4 | 5 };
}
```

<architecture>
- 스택: Vite · React 18 · TypeScript(strict) · Vitest. 런타임 의존성 최소화.
- 계층: `src/domain`(순수 함수, React·브라우저 API 금지) → `src/infra`(저장소 포트 + localStorage 어댑터, .ics 생성, 알림) → `src/ui`.
- 모든 점수 함수는 `RuleHit { ruleId, label, delta, block? }` 배열을 반환하고, UI는 이것을 그대로 보여 준다.
- 상태 전이(야식 퍼널)는 순수 함수로 만들고 UI는 상태만 들고 있는다.
- 저장소는 `HealthRepository` 인터페이스 뒤에 둔다. 기록 저장은 try/catch로 감싸 사생활 보호 모드에서도 화면이 동작해야 한다.
- UI 원칙: 폰 한 손 사용, 하단 탭, 판정은 색 + 아이콘 + 글자 세 가지로 표시(색만으로 구분 금지), 라이트·다크 모드, 입력창 글자 16px 이상(iOS 확대 방지), 존댓말로 짧게.
</architecture>
